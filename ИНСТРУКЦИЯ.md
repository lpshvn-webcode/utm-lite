# UTM Аналитика: запуск и настройка

Что это: Google Таблица со встроенным дашбордом. Она сама забирает заявки из CRM и расход из Meta, раскладывает заявки по каналам по UTM-меткам и показывает расход, заявки, продажи и окупаемость. Всё живёт в твоём Google-аккаунте.

Время на запуск: около 30 минут.

Как это устроено: страница дашборда одна для всех и лежит на GitHub Pages. Она только рисует интерфейс. Данные, токены и расчёты живут в твоей таблице Google, страница получает их по твоему коду и паролю.

## Что подготовить

| Что | Где взять |
|---|---|
| Google-аккаунт | на нём будет жить таблица; лучше рабочий, а не личный сотрудника |
| amoCRM: долгосрочный токен | amoCRM → amoМаркет → ⋯ → Создать интеграцию → Ключи и доступы → Долгосрочный токен |
| или Bitrix24: входящий вебхук | Разработчикам → Другое → Входящий вебхук, права CRM (crm). Подходит только облачный Bitrix24 |
| Meta: токен и номер кабинета | токен системного пользователя с правами `ads_read`; номер кабинета — цифры из Ads Manager (без `act_`) |
| UTM-метки | список меток, которыми размечена реклама: что стоит в `utm_source`, `utm_medium` и т.д. |

## 1. Установка

Самый простой путь: отдать файл `INSTALL.md` своему Claude Code. Он сам поставит инструменты, создаст таблицу, зальёт код и выдаст ссылку на дашборд. От тебя понадобятся три действия, которые Google не даёт сделать за владельца аккаунта: войти в Google, включить Apps Script API и разрешить скрипту доступ при первом запуске.

После установки в таблице появится меню **UTM Аналитика**:

| Пункт | Зачем |
|---|---|
| Открыть дашборд | запасной вход внутри Google (в браузере с несколькими аккаунтами Google работает только в инкогнито) |
| Первичная настройка | создаёт листы и включает ночное обновление в 03:00 |
| Задать пароль администратора | от 12 символов и минимум три вида знаков, либо фраза от 20 символов |
| Синк сейчас | обновить данные вручную |
| Сбросить блокировку входа | если вход закрылся после неверных паролей |

## 2. Ссылка на дашборд

Ссылка выглядит так: `https://lpshvn-webcode.github.io/utm-lite/#<код>`. Часть после `#` — код твоего дашборда, без неё страница не знает, чьи данные показывать. Ссылку можно давать сотрудникам и клиентам: без пароля в дашборд не войти.

На экране входа написано «Дашборд …» и последние 6 знаков кода. Они должны совпадать с концом твоей ссылки. Если не совпадают — пароль не вводи.

## 3. Настроить в дашборде

Открой ссылку, войди паролем администратора, зайди в **Настройки** и пройди разделы по порядку.

| Раздел | Что сделать |
|---|---|
| Подключения | выбери CRM, впиши адрес и токен; впиши номер кабинета Meta и токен; нажми «Проверить подключения» — оба пункта должны стать зелёными |
| Квалификация и продажа | «Обновить стадии из CRM», затем отметь стадии, с которых заявка считается квалифицированной, и стадии продажи |
| Каналы | создай правила (см. ниже) |
| Ручной расход | впиши расход по каналам, которых нет в Meta: канал, период, сумма |
| Доступ | задай пароль просмотра для сотрудников и клиентов. Он должен отличаться от пароля администратора. Кнопка «Придумать пароль» сделает надёжный |
| Оформление | название и логотип |
| Синк | «Запустить синк». Первая загрузка идёт 1–5 минут |

### Как работают правила каналов

Правило отвечает на вопрос «заявки с какими метками относятся к этому каналу».

| Поле | Что писать |
|---|---|
| пусто | подходит любое значение |
| `instagram` | точное совпадение, регистр не важен |
| `insta*`, `*cpc*` | звёздочка заменяет любую часть |

- Правила проверяются сверху вниз, заявка уходит в первое подошедшее. Узкие правила ставь выше широких.
- Заявка без единой метки попадает в «Без меток», с метками без правила — в «Прочие метки».
- Правило без меток заявок не забирает. Оно нужно для каналов только с расходом: радио, наружка.
- Откуда расход: «из Meta» (можно сузить по части названия кампании), «вручную» или «нет расхода».
- Расход Meta по кампаниям, которые не попали ни в один канал, показывается отдельной строкой и в итоги не входит.

Пример:

| Канал | utm_source | utm_medium | Расход |
|---|---|---|---|
| Таргет Instagram | `instagram` | `cpc` | из Meta |
| Блогеры | `blogger*` | | вручную |
| Рассылка | `email` | | нет расхода |
| Радио | | | вручную |

## Как пользоваться

| Экран | Что видно |
|---|---|
| Обзор | расход, заявки, квалы, продажи, выручка, цена заявки, ROMI и сравнение с прошлым периодом |
| Каналы | то же по каждому каналу; нажми на строку, чтобы раскрыть метки: source → medium → campaign → content → term |
| Заявки | список заявок с метками, каналом и статусом, ссылка на сделку в CRM |

Данные обновляются сами каждую ночь в 03:00. Вручную — Настройки → Синк, не чаще раза в 10 минут.

## Безопасность

- **Редактор таблицы — только владелец.** Кто может редактировать таблицу, тот видит токены CRM и Meta в настройках скрипта и может сменить пароль администратора. Сотрудникам и клиентам давай только ссылку на дашборд и пароль просмотра.
- Имена и телефоны клиентов из CRM не забираются и нигде не хранятся.
- В CRM дашборд ничего не пишет, только читает.
- После 10 неверных паролей вход закрывается на 15 минут для всех. Снять раньше: в таблице **UTM Аналитика → Сбросить блокировку входа**.
- Смена любого пароля сразу закрывает все открытые входы.

## Если что-то не так

| Что видишь | Что делать |
|---|---|
| Дашборд не открывается: «Не удалось открыть файл», в адресе появилось `/u/1/` или `/u/2/` | в браузере открыто несколько аккаунтов Google, и Google подставил не первый. Открой ссылку в окне инкогнито или в браузере, где выполнен вход только в один аккаунт |
| Нет меню «UTM Аналитика» | обнови страницу таблицы и подожди 10 секунд |
| На входе «Задай пароль администратора» | в таблице: UTM Аналитика → Задать пароль администратора |
| «В ссылке нет кода дашборда» | ссылка обрезана: нужна часть после `#` |
| «Проверить подключения» красное | текст рядом говорит, что не так: чаще всего истёк токен или неверный адрес CRM |
| Расход меньше, чем в Ads Manager | часть кампаний не попала в каналы — смотри строку «Расход Meta вне каналов» и поправь правила |
| Заявок меньше, чем в CRM | проверь период и воронки; данные за сегодня появляются после синка |
| Много заявок в «Без меток» | метки не доходят до CRM: проверь форму сайта и поля UTM в сделке |
| «Синк прерван по лимиту времени» | подожди 10 минут и запусти ещё раз |
| Ошибки синка | лист Log в таблице |
