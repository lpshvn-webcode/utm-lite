# INSTALL.md — установка «UTM Аналитики» через Claude Code

> Статус: путь через clasp ещё не пройден целиком на чистом аккаунте. Строки с пометкой ⚠ не проверены вживую.

Этот файл для Claude Code. Человек кладёт его в пустую папку, открывает папку в Claude Code и пишет: **«Установи UTM Аналитику по INSTALL.md»**.

## Что получится

Google Таблица в аккаунте человека со встроенным скриптом. Скрипт забирает заявки из CRM и расход из Meta, раскладывает заявки по каналам по UTM-меткам и отдаёт данные дашборду. Дашборд открывается по ссылке вида `https://lpshvn-webcode.github.io/utm-lite/#<код>`. Данные и токены живут только в аккаунте человека.

## Кто ты и как себя вести

Ты устанавливаешь продукт для владельца бизнеса или маркетолога. Он не программист. Говори по-русски, коротко, простыми словами. Команды запускай сам. Человека проси только о том, что отмечено 👤, по одному действию за раз, и жди ответа.

## Жёсткие правила

1. **Не проси и не принимай секреты в чат.** Токены CRM и Meta и пароли человек вводит сам: пароль администратора в окне таблицы, токены в дашборде. Если секрет попал в чат, скажи перевыпустить его и никуда не записывай.
2. **Не читай, не показывай и не копируй `~/.clasprc.json`**: там доступ к Google-аккаунту человека. Не запускай `env`, `printenv` и другие команды, которые печатают переменные окружения.
3. **Никаких `git add`, `git commit`, `git push`** в этой папке. Ты только скачиваешь код.
4. **Ничего не меняй в CRM и в рекламном кабинете.** Продукт их только читает.
5. **Не правь код продукта.** Если что-то не работает, покажи текст ошибки и остановись.
6. **Не говори «готово», пока не видел подтверждение**: вывод команды или текст с экрана человека. Не видел — так и скажи.
7. Устанавливай только то, что перечислено здесь, и только из указанных источников.
8. Не выдавай никому доступ к таблице и не советуй этого: редактор таблицы видит токены.

## Шаг 0. Вводные (один вопрос одним сообщением)

Спроси и запомни:
- CRM: amoCRM или облачный Bitrix24? Коробочный Bitrix24 не поддерживается — остановись и скажи об этом.
- Есть ли реклама в Meta и доступ к Business Manager, чтобы выпустить токен?
- В каком Google-аккаунте будет жить таблица? Лучше рабочий аккаунт компании, а не личный сотрудника.
- Название компании для шапки дашборда.

## Шаг 1. Инструменты

Проверь и поставь недостающее. Ничего не ставь глобально без необходимости.

```bash
node --version
git --version
```

- Node.js нужен версии 20 или новее. Нет или старее → macOS: `brew install node` (если есть Homebrew) или установщик с https://nodejs.org; Windows: `winget install OpenJS.NodeJS.LTS`. После установки проверь версию ещё раз.
- git нет → macOS: `xcode-select --install`; Windows: `winget install Git.Git`.

## Шаг 2. Код

```bash
git clone --depth 1 --branch v1.1.0 https://github.com/lpshvn-webcode/utm-lite utm-analytics
cd utm-analytics
npm ci
```

`npm ci` ставит одну зависимость строго той версии, что записана в репозитории: `@google/clasp`, официальный инструмент Google для Apps Script. Проверь: `npx clasp --version` печатает `3.4.1`. Другая версия или ошибка → остановись и покажи вывод. Не ставь clasp другим способом.

## Шаг 3. Вход в Google 👤

1. 👤 Попроси человека открыть https://script.google.com/home/usersettings и включить переключатель **Google Apps Script API**. Аккаунт на странице должен быть тот, что выбран в шаге 0.
2. Запусти:
   ```bash
   npx clasp login
   ```
   Откроется браузер. 👤 Человек выбирает тот же аккаунт и нажимает «Разрешить». Дождись в терминале строки `You are logged in as …`.
3. Проверь: `npx clasp show-authorized-user` показывает нужную почту. Другая почта → `npx clasp logout` и повтори вход.

Браузер не открылся → покажи человеку ссылку из терминала, пусть откроет её сам.

## Шаг 4. Таблица и скрипт

```bash
npx clasp create-script --type sheets --title "UTM Аналитика" --rootDir apps-script
```

Команда создаёт новую Google Таблицу с привязанным скриптом и печатает две ссылки: на таблицу и на скрипт. Сохрани обе в файл `INSTALLED.md` в этой папке.

⚠ `create-script` может перезаписать локальный `apps-script/appsscript.json` версией по умолчанию. Верни файл из репозитория и убедись, что в нём есть раздел `webapp`:

```bash
git checkout -- apps-script/appsscript.json
grep -c '"ANYONE_ANONYMOUS"' apps-script/appsscript.json
```

Должно напечатать `1`. Затем залей код:

```bash
npx clasp push --force
npx clasp show-file-status
```

Ошибка `User has not enabled the Apps Script API` → вернись к шагу 3.1, подожди минуту, повтори.

## Шаг 5. Первый запуск в таблице 👤

Это делает человек, за него нельзя: Google спрашивает разрешение у владельца аккаунта.

1. 👤 Открыть ссылку на таблицу из шага 4 и обновить страницу. Через 5–10 секунд в меню появится **UTM Аналитика**.
2. 👤 **UTM Аналитика → Первичная настройка.** Google спросит разрешение: выбрать аккаунт → «Дополнительные настройки» → «Перейти на страницу UTM Аналитика» → «Разрешить». Если после разрешения ничего не произошло, выбрать пункт ещё раз.
3. 👤 **UTM Аналитика → Задать пароль администратора.** От 12 символов и минимум три вида знаков (строчные, заглавные, цифры, прочие) либо фраза от 20 символов. Пароль человек придумывает и хранит сам, тебе его не сообщает.

Проверка: попроси человека назвать листы внизу таблицы. Должны быть Settings, Channels, Spend_Manual, Meta_Spend, CRM_Leads, Stages, Assets, Log.

## Шаг 6. Публикация

```bash
npx clasp create-deployment --description "UTM Аналитика"
```

Команда печатает код развёртывания: длинная строка, начинается с `AKfy`. Запиши его в `INSTALLED.md`.

Собери ссылку на дашборд: `https://lpshvn-webcode.github.io/utm-lite/#<код развёртывания>`.

Проверь, что сервер отвечает (вместо `<код>` подставь код развёртывания):

```bash
curl -sL -H "Content-Type: text/plain" -d '{"fn":"apiBoot","args":[]}' "https://script.google.com/macros/s/<код>/exec"
```

Команду не меняй: с ключом `-X POST` Google ответит ошибкой 405. Ожидаемый ответ: JSON с `"ok":true` и `"needsSetup":false`.

| Ответ | Что значит | Что делать |
|---|---|---|
| `"needsSetup":true` | пароль администратора не задан | шаг 5.3 |
| страница HTML с просьбой войти | развёртывание не открыто для всех | проверь раздел `webapp` в `appsscript.json`, повтори `clasp push --force` и шаг 6 ⚠ |
| HTML «Требуется авторизация» или ошибка скрипта | владелец ещё не дал разрешение | шаг 5.2 |

## Шаг 7. Настройка в дашборде 👤

Дай человеку ссылку на дашборд. Он входит паролем администратора и идёт в **Настройки**. Веди его по разделам, сам ничего не вводи.

| Раздел | Что делает человек | Откуда взять |
|---|---|---|
| Подключения → CRM | тип CRM, адрес, токен | amoCRM: amoМаркет → ⋯ → Создать интеграцию → Ключи и доступы → Долгосрочный токен. Bitrix24: Разработчикам → Другое → Входящий вебхук, права CRM |
| Подключения → Meta | номер кабинета (цифры без `act_`), токен, валюты | Business Manager → Системные пользователи → токен с правом `ads_read`, пользователю выдан рекламный кабинет |
| Подключения | кнопка «Проверить подключения» | обе строки должны стать зелёными |
| Квалификация и продажа | «Обновить стадии из CRM», отметить стадию квалификации и все стадии после неё; стадии продажи | если продажу не отмечать, считается системная «Успешно» |
| Каналы | правила (см. ниже) | примеры меток из сделок CRM |
| Ручной расход | канал, период, сумма | для каналов без рекламного кабинета |
| Доступ | пароль просмотра, отличный от администраторского | его дают сотрудникам и клиентам |
| Оформление | название, логотип | |

Что пишет проверка подключений:

| Текст | Причина | Что делать |
|---|---|---|
| amoCRM 401 | токен неверный или истёк | выпустить новый долгосрочный токен |
| адрес amoCRM не принят | нужен вид `имя.amocrm.ru` или `имя.kommo.com` | вписать поддомен или адрес без `https://` |
| вебхук Bitrix24 не принят | нужен вид `https://имя.bitrix24.kz/rest/1/ключ/` | скопировать вебхук целиком, без имени метода в конце |
| Meta 190 | токен истёк или отозван | выпустить токен системного пользователя |
| Meta 100 или 200 | нет доступа к кабинету или права `ads_read` | выдать системному пользователю кабинет и право |

### Правила каналов

Попроси 5–10 реальных примеров меток (ссылки из рекламы или значения из сделок). Предложи таблицу правил, покажи человеку, после согласования он вводит их сам.

- Пустое поле = любое значение. Текст = точное совпадение без учёта регистра. `*` заменяет любую часть: `insta*`, `*cpc*`.
- Порядок важен: заявку забирает первое подошедшее правило. Узкие правила выше широких.
- Правило без меток заявок не забирает: это канал только с расходом (радио, наружка).
- Расход канала: из Meta (можно сузить по части названия кампании; кампания уходит в первый подходящий канал), вручную или нет.
- Название и значения не начинаются с `=`, `+`, `-`, `@`.
- Заявки без меток попадают в «Без меток», с метками без правила — в «Прочие метки».

## Шаг 8. Первый синк и сверка

1. 👤 Настройки → Синк → «Запустить синк». До 5 минут.
2. Попроси цифры с экрана «Обзор» за последние 7 дней и сверь с источниками:
   - заявки = сделки, созданные в CRM за те же дни;
   - расход = Ads Manager за те же дни плюс ручной расход. Меньше → на экране есть строка «Расход Meta вне каналов», поправьте правила;
   - продажи и выручка = сделки в стадиях продажи.
3. Расхождения ищи на листе Log (человек читает тебе строки с ERROR) и на экране «Каналы»: большая доля «Без меток» значит, что метки не доходят до CRM.

## Шаг 9. Передача

Запиши в `INSTALLED.md` ссылки на таблицу, скрипт и дашборд, код развёртывания и дату. Паролей и токенов там быть не должно.

Выйди из Google на этом компьютере, чтобы доступ к аккаунту не остался лежать на диске:

```bash
npx clasp logout
```

Для обновления потом понадобится войти снова (шаг 3.2). Скажи человеку:

- ссылку на дашборд и пароль просмотра можно давать сотрудникам и клиентам;
- доступ к самой таблице не давать никому;
- данные обновляются сами каждую ночь в 03:00, вручную — кнопкой в разделе Синк;
- ссылку на дашборд сверяйте по окончанию: на экране входа написано «Дашборд …» и последние 6 знаков кода, они должны совпадать с концом вашей ссылки. Чужая ссылка на том же сайте с вашим названием — повод не вводить пароль;
- если вход заблокирован после неверных паролей (10 попыток, блок на 15 минут): в таблице **UTM Аналитика → Сбросить блокировку входа**;
- запасной вход, если страница дашборда недоступна: в таблице **UTM Аналитика → Открыть дашборд**. В браузере с несколькими аккаунтами Google он открывается только в окне инкогнито.

## Обновление

```bash
cd utm-analytics
git fetch --tags && git checkout <новый тег, который назвал владелец продукта>
npm ci
npx clasp login
npx clasp push --force
npx clasp create-deployment --deploymentId <код развёртывания> --description "обновление"
```

После обновления: `npx clasp logout`. Ссылка на дашборд при этом не меняется. ⚠

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| `clasp login` не завершается | человек не нажал «Разрешить» в браузере; открыть ссылку из терминала вручную |
| `Project file already exists` при создании | скрипт уже создан: в папке `apps-script` есть `.clasp.json`, шаг 4 повторять не нужно |
| В таблице нет меню «UTM Аналитика» | код не залит (повтори `clasp push --force`) или страница не обновлена |
| Дашборд пишет «В ссылке нет кода дашборда» | ссылка обрезана: нужна часть после `#` |
| Дашборд пишет «Нет связи» | проверь команду `curl` из шага 6 |
| Синк отвечает `too_soon` | прошлый синк был меньше 10 минут назад |
| «Синк прерван по лимиту времени» | подождать 10 минут и запустить ещё раз |

## Справка по устройству

| Лист | Что в нём |
|---|---|
| Settings | настройки без секретов |
| Channels | правила каналов |
| Spend_Manual | ручной расход |
| Meta_Spend | расход Meta по дням и кампаниям |
| CRM_Leads | сделки: стадия, сумма, метки; без имён и телефонов |
| Stages | воронки и стадии CRM |
| Log | журнал синка и ошибок |

Листы руками не правятся. Токены и хеши паролей лежат в свойствах скрипта и наружу не отдаются.
